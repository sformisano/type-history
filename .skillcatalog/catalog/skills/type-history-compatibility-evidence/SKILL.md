# Type History compatibility evidence

Use this skill when claiming a Type History change still reads retained records
correctly. Read [decoding](https://github.com/sformisano/type-history/blob/main/book/src/decoding.md)
and [codec guarantees](https://github.com/sformisano/type-history/blob/main/book/src/integration.md#codec-guarantees)
at the revision matching the consumer's locked dependency. Those documents own
the supported formats, APIs, and error details.

## Keep the evidence independent

Use fixed historical bytes whose origin is independent of the implementation
under test: retained released output, captured records, or independently authored
format fixtures. Write the expected current values from the domain meaning of
those records, independently of the conversion code.

Cover affected retained source versions through the complete conversion path to
the current type. Test the codecs the application actually uses. Include cases
where the change can lose information, overflow, or lack a required fact, along
with valid records that should succeed. The
[payment tests](https://github.com/sformisano/type-history/blob/main/crates/examples/invoice-history/tests/payment.rs)
and [fixture rules](https://github.com/sformisano/type-history/blob/main/crates/examples/invoice-history/tests/fixtures/README.md)
show old JSON and MessagePack bytes checked against separately written current
values.

Keep historical fixtures when adding a version. Replacing them with bytes
generated by the new code removes their historical evidence. A latest-version
round trip proves agreement between today's writer and reader; it cannot prove
that yesterday's bytes retain their meaning.

## Separate structure from conversion meaning

A frozen ledger protects the retained storage structure. It does not freeze the
meaning of conversion callbacks: editing a callback can change old replay while
the ledger and current version stay unchanged. Recheck affected historical
results when changing those callbacks, even if schema checks pass.

Distinguish failure to decode the selected historical payload from failure to
convert a valid historical value. For an expected conversion failure, verify the
original source version, the failing adjacent step, and the application-relevant
cause described in the decoding docs. Match the compatibility claim to the
versions, codecs, successful meanings, and failure cases the evidence covers.
